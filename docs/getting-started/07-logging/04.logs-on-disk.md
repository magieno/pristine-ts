# Logs on disk

**`@pristine-ts/observability`** captures logs and traces to a structured store under
`.pristine/observability/` that the CLI can query by event, trace or request id.

`CliModule` and `HttpModule` both import `ObservabilityModule`, so **most apps capture to
disk by default**. A non-CLI, non-HTTP app imports `ObservabilityModule` directly.

```sh
PRISTINE_OBSERVABILITY_ENABLED=false   # turn capture off entirely
```

## Reading what was captured

```sh
pristine logs                    # newest 1000 entries across all processes
pristine logs <eventId>          # filter by event / trace / request id
pristine logs -f                 # follow live
pristine logs --limit 0          # everything (can be a lot)
pristine requests --limit 20     # recent requests, one line each
pristine trace <eventId>         # the full span tree for one request
```

## Layout

```
.pristine/observability/
  <instanceId>/logs.jsonl         # one JSON line per captured log entry
  <instanceId>/logs.1.jsonl       # rotated generations, 1 = most recent
  <instanceId>/requests.jsonl     # one summary per completed trace
  <instanceId>/traces/<eventId>.json
  <instanceId>/pid                # the owning process
```

Each `<instanceId>` is one process lifetime (the kernel instantiation id), so concurrent
processes never race on the same file. Readers walk every instance directory newest-first;
the partitioning is invisible to `pristine logs`.

## Disk usage

**The store is capped at 100 MB.** To change the budget:

```sh
PRISTINE_OBSERVABILITY_MAX_STORE_SIZE=524288000   # 500 MB
PRISTINE_OBSERVABILITY_MAX_STORE_SIZE=0           # no byte ceiling (count/age only)
```

| What it bounds | Configuration key | Default |
|---|---|---|
| The whole store | `pristine.observability.maxStoreSize` | 100 MB |
| One live `.jsonl` file | `pristine.observability.maxLogFileSize` | 10 MB |
| Generations kept per `.jsonl` | `pristine.observability.maxLogFiles` | 3 |
| Trace files per instance | `pristine.observability.maxTraceFiles` | 500 |
| One trace file | `pristine.observability.maxTraceFileSize` | 1 MB |
| One log entry | `pristine.observability.maxEntrySize` | 64 KB |
| Instance directories kept | `pristine.observability.retainedInstances` | 10 |
| How long they are kept | `pristine.observability.maxRetentionAgeInMilliseconds` | 7 days |
| Minimum severity captured | `pristine.observability.logSeverityLevelConfiguration` | `SeverityEnum.Info` |

Every key has a `PRISTINE_OBSERVABILITY_…` environment variable (screaming snake case of
the key's last segment).

The severity threshold is the store's own — it does **not** follow
`pristine.logging.logSeverityLevelConfiguration`, because the store bypasses `BaseLogger`.
Lower it to `SeverityEnum.Debug` (`0`) to capture everything, raise it to
`SeverityEnum.Warning` (`4`) on a chatty service.

## What happens at the limits

- An entry over `maxEntrySize` is rewritten **without its `extra` payload** and flagged
  `extraOmitted`. `extra` is the unbounded part — it routinely holds whole span trees —
  and dropping it keeps `eventId` / `traceId` / `severity` / `message`, so the entry still
  shows up in a filtered query.
- A `.jsonl` file over `maxLogFileSize` rolls over to `<name>.1.jsonl`. Readers
  concatenate the generations, so history survives a rollover and `pristine logs --follow`
  picks up the new file transparently.
- A trace tree over `maxTraceFileSize` is **not written**; its summary still is, flagged
  `traceOmitted`, so `pristine requests` keeps listing the request.
- When the store as a whole exceeds `maxStoreSize`, a sweep reclaims in order: instance
  directories past the age/count limits, then whole abandoned directories oldest-first,
  then individual rotated generations and trace files. A running process's *live*
  `logs.jsonl` / `requests.jsonl` is never deleted out from under it — ownership is
  tracked through the `pid` sidecar, so concurrent workers never delete each other's data.

## Pitfalls

- **Ephemeral filesystems.** In a container the store dies with the container. Keep
  streaming stdout to your aggregator; treat this store as a local debugging and
  incident-triage tool, not as your log retention system.
- **The store is capped in bytes, not in entries.** `pristine logs --limit 0` on a full
  100 MB store renders a very large number of lines. The default `--limit 1000` exists for
  that reason.
- **Capture is on by default.** Any HTTP app writes to `.pristine/observability/` unless
  you set `PRISTINE_OBSERVABILITY_ENABLED=false`. Add `.pristine/` to `.gitignore`
  (`pristine init` does).
- **Retention applies to what is already there.** A sweep enforces the current limits
  against the whole store, so lowering `maxStoreSize` reclaims on the next append rather
  than only from that point forward.
